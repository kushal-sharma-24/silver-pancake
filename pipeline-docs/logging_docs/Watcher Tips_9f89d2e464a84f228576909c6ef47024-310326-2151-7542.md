## **Two services, one watch** 

Some teams have way too many watches, and they might not want to duplicate them, but meantime watch it as two different services. Or there might be some other reasons, to have just one watch for it. 

It is possible, but is not a trivial, and some scripting needs to be done. 

Example (in this case, I use real watch definition):

## Create watch condition to compare percentage rate of two queries 

Usually watches are based on comparison of predefined threshold number to the count of some specific documents. However, there are cases where comparison of percentage of different queries is more useful (i.e. booking attempts vs. successful bookings, # of errors vs. # of transactions, ...). 

Here is how such watch definition can be created. 

**Limitations** : cannot compare data from different indexes 

**Solution** : 

- first, create a query that includes both results you want to compare in the output. In my example you see the query, which asks for both **booked and attempt** 

- create top-level aggregation, which is only a placeholder (main part - bucket_script aggregation cannot be on top level aggregations). I used date_histogram with month interval (obsolete, as you are usually asking only for few minutes of data) create data aggregation definitions. These will be later used to compute the final value. In the example, those are attempts-data and booked-data. As you can see, I use filter aggregation type, to filter out only specific values, and then inner count aggregations (as we need the count) at the end, compute the values in bucket_script aggregation, where you first need to define variables (bucket_path). Notice the path (attemptsdata>c) and then use those variables in the script follow this example... 

Watch definition query example: 

```
{
  "size": 0,
  "query": {
    "bool": {
      "must": [{
        "query_string": {
          "query": "cte.subcategory:\"Air Booked (GDS/DC)\" OR cte.subcategory:\"Air Book Attempt (GDS/DC)\""
        }
      },
      {
        "range": {
          "@timestamp": {
            "from": "now-5m",
            "to": "now"
          }
        }
      }]
    }
  },
  "aggs": {
    "month": {
      "date_histogram": {
        "field": "@timestamp",
        "interval": "month"
      },
      "aggs": {
        "attemptsdata": {
          "filter": {
            "term": {
              "cte.subcategory.analyzed": "attempt"
            }
          },
          "aggs": {
            "c": {
              "value_count": {
                "field": "cte.subcategory"
              }
            }
          }
        },
        "bookeddata": {
          "filter" : {
            "term": {
              "cte.subcategory.analyzed": "booked"
            }
          },
          "aggs": {
            "c": {
              "value_count": {
                "field": "cte.subcategory"
              }
            }
          }
        },
        "bookedpercentage": {
          "bucket_script": {
            "buckets_path": {
              "attempts": "attemptsdata>c",
              "booked": "bookeddata>c"
            },
            "script": "booked / attempts * 100"
          }
        }
      }
    }
  }
}
```

The above query returns such result, so you should use **aggregations.month.buckets[0].bookedpercentage.value** as threshold field in your watch definition, and compare it to 100 for ex, or whatever is your threshold success rate % for bookings vs attempts.

## Create watch notification to alert you on Slack channel via Slack incoming webhook integration 

You can create watch which alerts you on Slack using Slack bot and Slack webhook integration.  To do this, follow these steps: 

Set up incoming webhook integration for Slack channel you would like to use, do it on https://my.slack.com/services/new/incoming-webhook/ Create new watch definition with webhook action, see sample on https://github.concur.com/cia/watcher/blob/master/action-webhook.json . Define the webhook action to POST to Slack webhook url from step 1. 

```
POST https://hooks.slack.com/services/T00000000/B00000000/XXXXXXXXXXXXXXXXXXXXXXXX
Content-type: application/json
{
    "text": "This is a line of text.\nAnd this is another one."
}
```

You can customize Slack bot name, emoji/icon, include links or emojis on your text.  See more on https://api.slack.com/incoming-webhooks . 

Further examples can be found in a github repostitory: https://github.concur.com/cia/watcher
